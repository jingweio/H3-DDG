## 1. Goal / hypothesis

本 task **不是**最终目标，而是 BindingGYM 复现的**前置正确性验证**（用户明确要求「完整复现 SKEMPI Table 1」）。

- **要验证的事**：H3-DDG 官方 released code（只含 SKEMPI 路径）在我们搭建的 env / ProteinMPNN ckpt / a100 上，能复现论文 Table 1 的数值。
- **为什么必须先做**：BindingGYM 的 pipeline（dataset loader / split / metrics）**官方没有发布，需要我们自己重实现**。若不先确认 model + env 本身无误，一旦 BindingGYM 结果对不上，将无法区分是「我们的 BindingGYM 实现有问题」还是「模型代码/环境有问题」。
- **判定标准**：all-mutation Overall Pearson ≈ 0.7501、Spearman ≈ 0.6604、RMSE ≈ 1.3665、AUROC ≈ 0.7920；per-structure Pearson ≈ 0.5686 / Spearman ≈ 0.5281。允许 seed/硬件带来的小幅偏差。

### 2.2 KEY DECISIONS（选项 + 理由）

1. **超参：用作者 repo 的 `config/train_h3-ddg.json` 原样**（用户决定）。
   - `lr=4e-5`、`max_iter=38000`、`num_cvfolds=3`、`batch_size=1`、`hidden_dim=128`、`num_layers=3`、`num_edges=48`、`num_tri_heads=4`、`use_hypergraph=true`、`hyper_ratio=4`（即 L/4 hyperedges）、`num_edges_ratio=3.0`（即 3N 4-body edges）、`edges_selection=dynamic`、`seed=42`。
   - ⚠️ **与论文 Appendix A.4 不一致**：论文写 `lr=4e-4`、`20,000 iterations`。git log 里还有一次 `Modify the parameter max_iter` 的 commit。本前置实验按用户决定**以 repo config 为准**；BindingGYM 主实验则按论文 appendix。
   - 唯一改动：`ckpt_path` 由占位符 `"path_to_ckpt"` 改为 `"./data/v_48_020.pt"`（README 明确要求用户自行填写此项）。

2. **split：作者代码内置的 3-fold by complex**（`skempi.py:66`，`random.Random(3745754758).shuffle(complex_list)`，与 Prompt-DDG 同一 seed）。不做任何修改。

3. **`3VR6_ABCDEF_GH` 的特殊处理保持原样**：作者代码因显存原因把它从 train split 剔除（`skempi.py:77` + `train_skempi.py:64`）。保留该行为以忠实复现。

4. **GPU：a100 ×1**（skill 默认；`sinfo` 显示 a100 充足，无需 v100 fallback）。论文用的是 RTX 4090（24 GB），a100-80GB 显存更充裕，不会因 OOM 改变行为。

5. **评测口径**：直接用 repo 的 `eval_skempi_three_modes`（all / single / multiple 三种 mutation 模式 + per-structure 分组，≥10 条突变的 structure 才计入），与论文 Appendix A.3 描述一致。训练结束后 `validate()` 汇总 3 个 fold 的 `results.csv`。

6. **⚠️ 必须保留 500-iter 的在线验证节奏**（`val_freq=500`，且 `max_iter=38000 < 50000` 走的是「从第 1 个 iteration 起每 500 步验证一次」的分支）。原因：README 要求训练后跑 `validate_all.py --top_k K`，而它的输入正是这些中间产物 `fold{f}_its{its}_results.csv`。
   - 📌 **方法学备注（记录在案）**：`validate_all.py:72-74` 按**每个 fold 自己的验证 Spearman** 选出 top-k 个 iteration，再枚举 k³ 种组合逐一报告合并指标。而 SKEMPI 这条线里 **val fold 就是 test fold**（无独立验证集），因此这等于**在评测集上做模型选择**。这是作者的既定协议，我们忠实复现，但报告时会显式标注。
   - 代价：3 folds × 76 次全量验证（每次 ~2500 条）是主要耗时来源。
