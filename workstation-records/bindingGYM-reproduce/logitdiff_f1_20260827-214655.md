# bindingGYM-reproduce — H3-DDG × BindingGYM readout 修正臂（logitdiff），fold 1
（created 2026-08-27；status: **PLANNED**）

## 1. Goal / hypothesis

**问题**：H3-DDG 的热力学循环 readout `ΔΔG = (E_mut^complex − E_mut^side) − (E_wt^complex − E_wt^side)`
假设 label 是**结合自由能变化**。BindingGYM 的 label 是 DMS fitness / enrichment score（酵母生长、
分选富集、功能打分），**不具备自由能含义** —— 用循环去拟合它等于强加了一个数据没有的物理解释。
（用户判断，2026-08-26）

**假设**：换成 BindingGYM 自己的 readout（`log p(mut|backbone) − log p(wt|backbone)`，只对 complex
一次前向）后，H3-DDG 在 BindingGYM 上的表现应显著改善。

**对标**（fold 1，per-DMS 等权 Spearman）：

| | ALL |
|---|---|
| A.4 口径（裸 MSE / batch 1 / 全 assay 混采） | 0.0904 |
| strategy 臂（同 assay batch + listMLE，仍用循环）| **0.2311** |
| bgymfull 臂（+ BindingGYM optimizer，仍用循环）| ep10 **0.0145** / ep20 **0.0417** |
| **本臂（logitdiff）** | **待测** |
| 论文 Table 2 | 0.2725 |
| 官方 ProteinMPNN 微调，f1 分项（本项目重构）| 0.2719 |

## 2. Design & decision points

### 归属划分：只保留 H3-DDG 的架构 + `backbone_noise=0.0`，其余全部 BindingGYM

| 项 | 来源 | 值 |
|---|---|---|
| 架构（hypergraph pooling + 3-body/4-body attention）| H3-DDG | 与 `config/train_h3-ddg.json` **逐字段一致** |
| **`backbone_noise`** | **H3-DDG（唯一保留的例外）** | **0.0**（官方是 `augment_eps 0.2`）|
| **readout** | **BindingGYM** | `logit_diff`：一次前向、只对 complex、`mut_nll − wt_nll` |
| optimizer / scheduler | BindingGYM | AdamW lr 1e-3, wd 0.05, eps 1e-5, OneCycleLR |
| loss | BindingGYM | listMLE |
| batch 组成 / assay 采样 | BindingGYM | 同一 assay / 均匀 |
| epoch 结构 | BindingGYM | 256 步/epoch |
| 停止规则 | **用户决定的偏离** | **无早停**，固定 50 epoch，每 10 epoch 评全量 → 5 个 checkpoint |

**为何去掉早停**（用户 2026-08-25）：H3-DDG 每次评测远比朴素 ProteinMPNN 贵，官方的「每 epoch 评全量」
在 f1 上是 50 × 1.0h = 50h；改成 5 次全量评测只要约 3h，且产出的是一条轨迹而非单点。这是对
BindingGYM `patience 3` 的一处刻意偏离，其余字段仍全是官方的。

### KEY DECISIONS（本次在 workstation 上追加的）

- **`batch_size` 让探测取 8**（用户拍板）。实测 `logit_diff` 每前向行 **5.44 GiB**（1016 残基的
  `4D5_HER2`，f1 训练集最大结构），slate 8 ≈ **44 GiB**，开跑前空闲 65 GiB。
  **这将是第一次真正用满 BindingGYM 的 batch size** —— 之前 `cycle` readout 每 item 要 2 个前向行，
  A100-80GB 上只能到 4。slate 长度翻倍意味着 listMLE 学的是 8 元排列而非 4 元。
  ⚠️ 风险：卡上另有 3 个别人的进程（15.7 GiB），若再增长超过 21 GiB 会 OOM —— 但有 `--resume`
  （逐 epoch 存点），最多丢一个 epoch，且 workstation 无排队成本。
- **远端路径用 `/data/guoj0f/repos/H3-DDG/reproduce/` 而非 skill §7 写的 `/home/...`**。
  理由：整棵树 1.8 GB，而 `/home` 已 98% 满、仅剩 158 G（§2 明令 GB 级的东西进 `/data`）。
  放 `/data` 让代码+数据自包含、相对路径不用改，且不碰紧张的 `/home`。**建议并入 skill**（见 §4）。
- **不同步 `bgym_official/`**（602 MB）—— 那是姊妹 project 的 vendored 官方代码，本臂用不到。
